# SDD 开发流程约定

本项目采用规格驱动开发（Specification-Driven Development）。本文件约束每个模块的生命周期。

## 模块生命周期（不可跳步）

1. **写规格** `docs/specs/NN-<module>.md`，必须包含：
   - 范围（做/不做，引用合同章节号）
   - 领域规则（逐条编号 R1、R2…，可直接转成测试用例）
   - 数据模型（表、列、唯一约束、索引，与迁移脚本一致）
   - API 契约（方法、路径、请求/响应、错误码）
   - 幂等与并发规则
   - 验收标准（对照合同 §18 逐条映射）
2. **自检规格**：对照合同与交叉评审逐条核对，确认无冲突、无超范围功能（合同 §7 收敛约束）。
3. **写迁移**：`migrations/NNNN_<name>.sql`，DDL 与回填分离。
4. **写代码**：先 store（SQL）→ 再 service（规则）→ 后 handler（适配）。跨模块只调 service 接口。
5. **写测试**：领域规则单测（每条 R 至少一个用例）；集成测试打 `//go:build integration` 标签，靠 `WECHAT_TEST_MYSQL_DSN` 启用。
6. **更新总账**：`docs/PROGRESS.md` 里程碑表 + 会话日志。

## 复杂度分治规则

- 一个模块超过 ~800 行业务逻辑时，按"读路径/写路径/状态机"拆文件，不拆模块。
- 跨模块流程（如"同意好友申请→建会话"）由发起方 service 编排，被调方只提供原子能力；禁止双向依赖。
- Worker 任务（阶段二起）统一走 Outbox → Relay/直读 → Inbox 幂等消费，禁止业务代码直连 mq。

## 技术债红线（违反即返工）

- 跨模块直读/直写他方数据表。
- 绕过 service 在 handler 里写业务规则。
- 在 Redis/RabbitMQ/内存里存唯一事实状态。
- 引入合同 §7 禁止的能力（搜索引擎、工作流引擎、通用权限 DSL、已读回执、在线状态等）。
- 在阶段一范围外"提前铺路"的半成品代码（ADR-010）。
- 本地时区时间入库；float 存金额/尺寸；无索引的 LIKE 全表扫。

## 提交物检查单（每个模块完成时）

- [ ] 规格与代码行为一致（规则编号可互相引用）
- [ ] `go build ./...`、`go vet ./...` 通过
- [ ] 领域单测通过
- [ ] 迁移可重复执行（goose up/down）
- [ ] PROGRESS.md 已更新
